# Learning-based Active Perception and Recovery for Robust Robotic Manipulation
## 기술 타당성 분석 (구현 전 설계 검토, 코드 작성 없음)

## 0. 결론 먼저 — 가장 급한 블로커

**Isaac Sim은 NVIDIA RTX 계열 GPU(실시간 레이트레이싱 지원)를 사실상 필수로 요구한다.** 지금 작업 중인 머신은 hostname `wynz-NUC11PHi7`로, Intel NUC 11 Pro 계열 소형 PC다. 이 라인업은 보통 내장 그래픽(Iris Xe) 또는 저전력 외장 GPU 구성이라, Isaac Sim 공식 권장 사양(RTX 3080급 이상, 최소 RTX 2070급)에 못 미칠 가능성이 높다. **이건 "시간이 더 걸린다" 수준의 리스크가 아니라 "이 경로 자체가 이 머신에서 아예 안 돌아갈 수 있다"는 하드 블로커**이므로, 아래 전체 로드맵을 확정하기 전에 가장 먼저 `nvidia-smi`로 실제 GPU 모델/VRAM을 확인해야 한다. (다른 워크스테이션/서버에서 학습하고 정책만 이 머신으로 가져와 실물에 배포하는 구성도 가능하니, GPU가 없다고 전체 방향이 막히는 건 아니다 — 다만 "이 노트북에서 전부 돌린다"는 가정은 재검토가 필요하다.)

## 1. 재사용 가능 vs 신규 개발

**재사용 가능 (이미 실물 검증됨):**
- `Fr3Motion`(MoveIt2 OMPL+Cartesian 플래닝, link8↔fr3_hand_tcp 변환, 그리퍼 open/close/grasp, 테이블 충돌모델, 컨트롤러 activate/deactivate) — RL 정책이 고른 행동(grasp/move-to-viewpoint)의 **실행 레이어**로 그대로 사용
- ROS2 노드 구조·yaml 설정 분리 패턴(`object_pose_publisher`/`vision_pick_place` 식 구독-실행 구조) — 정책 추론 노드를 같은 패턴으로 추가 가능
- 안전장치(z 최소값 체크, collision object)

**신규 개발 필요:**
- eye-in-hand hand-eye 캘리브레이션 (기존 eye-to-hand solvePnP 방식은 폐기, "그리퍼로 기준점 터치" 노하우만 이식)
- 저차원 상태 추출기(물체 포즈 추정치+불확실도, 가림 정도, 파지 신뢰도) — **실물에서 먼저 신뢰성 검증 필요**, sim 여부와 무관하게 이게 안 되면 아무것도 안 됨
- 성공/실패/판정불확실 3단 분류기(트레이 점유 변화 + 그리퍼 정보 결합) — 아래 3절에서 구체화
- Isaac Sim 디지털 트윈(FR3+트레이+물체 물리, eye-in-hand 카메라 센서, 저차원 state 추출 로직)
- Isaac Lab Gym 환경 wrapper + RL 학습 루프
- Sim↔Real state 표현 정합성 검증 파이프라인

## 2. State / Action / Reward / Termination

**State (저차원, 요청하신 대로 이미지 직접 입력 안 함):**
- 물체 포즈 추정치(x, y, z, yaw) + 추정 불확실도(공분산 또는 스칼라 신뢰도)
- 가림 정도(0~1, segmentation/raycast 기반 가시 면적 비율)
- 파지 신뢰도(검출된 폭 대 목표 폭 정합도, 또는 학습된 affordance 점수)
- 현재 카메라/엔드이펙터의 상대 시점(이미 어디서 봤는지 정책이 알아야 같은 곳을 반복 안 함)
- 이력: 현재 에피소드 내 재관측 횟수, 재시도 횟수, 경과 스텝 수

**Action (이산, 요청하신 4가지 결정에 대응):**
- `GRASP`: 현재 추정 포즈로 파지 시도
- `REOBSERVE(i)`: 사전 정의된 후보 시점 집합 {1..K}(K=4~6 권장, 연속 6D가 아니라 이산 집합으로 제한해야 Isaac Lab 학습이 현실적) 중 i번 시점으로 이동 후 재관측
- `ESCALATE`: 작업 포기/사람 개입 요청 (종료 행동)

**Reward:**
- 성공(3단 분류기가 "성공" 판정) 도달: `+R_success`
- `REOBSERVE` 1회당: `-c_obs`(작고 고정된 비용 — 시간/마모)
- 실패한 `GRASP` 시도 1회당: `-c_grasp`(`c_obs`보다 큼 — 물체 교란·충돌 위험·시간 더 큼)
- `ESCALATE`: `-c_escalate`(중간 크기 — 실패보다는 낫지만 성공보다 훨씬 나쁨)
- 최대 스텝 초과(truncation): `-c_timeout`(가장 나쁜 결과로 설계해 무한정 관측만 반복하는 정책을 방지)
- "판정불확실" 상태는 종료 신호로 쓰지 않고, 에이전트가 `REOBSERVE`를 선택하도록 유도하는 **중립~약한 음수 보상**으로 설계(섣부른 성공 선언 방지)

**Termination:**
- 종료: `GRASP` 성공 판정, 또는 `ESCALATE` 선택
- 중단(truncation): 최대 스텝(재관측+재시도 합산) 초과
- 비종료: `GRASP` 실패(최대 재시도 미도달) 또는 `REOBSERVE` 실행 — state 갱신 후 계속

## 3. 성공/실패/판정불확실 3단 분류 (요청하신 대로 단순 점유 변화만으로 단정하지 않음)

트레이 점유 변화(1차 신호)를 다음 보조 신호와 결합:
- 그리퍼 폭 판정 결과(물리적으로 뭔가를 물었는지)
- 출발 트레이 객체 수 감소 여부 + 도착 트레이 객체 수 증가 여부(둘 다 맞아야 "성공", 하나만 맞으면 "불확실" — 예: 집었지만 이동 중 다른 곳에 떨어뜨린 경우 출발은 감소, 도착은 미증가)
- (선택) 재관측 시 해당 위치의 물체 외형이 이전과 동일한지(그대로면 완전 실패, 다르면 교란 발생 가능성 → 불확실)

이 3단 분류기 자체의 정밀도/재현율은 실물에서 사람이 라벨링한 소규모 세트로 **먼저 검증**해야 한다 — RL 보상이 이 분류기에 의존하므로, 분류기가 부정확하면 정책이 잘못된 신호로 학습된다.

## 4. 규칙 기반 Baseline vs 학습 기반 정책 비교 설계

| 조건 | 방식 |
|---|---|
| B0 | 현행 열린 루프(1회 검출-1회 이동) |
| B1 | 고정 재관측(같은 시점에서 재확인 후 재시도) |
| B2 | 휴리스틱 NBV(고정 순서로 사전 정의된 대안 시점 순회) — "규칙 기반 baseline" |
| RL | Isaac Lab에서 학습한 정책, 실물 전이 |

지표: 에피소드당 보상(주지표), 최종 성공률, 성공당 평균 재관측·재시도 횟수(효율성), 평균 소요시간, 에스컬레이션 비율, 미지 클러터/배치에 대한 일반화. 시뮬레이션에서는 대량(수백~수천 에피소드)으로, 실물에서는 조건당 30~50회 수준으로 검증(실물 시행은 비용이 크므로).

## 5. Sim-to-Real 전이 예상 문제 + 대응

| 문제 | 대응 |
|---|---|
| sim은 정확한 ground-truth state, real은 노이즈 있는 추정치 | 1단계(Phase 1)에서 실측한 실제 추정 오차 통계(예: 기존 캘리브레이션 작업에서 측정된 5.6~30mm급 오차)를 sim의 state 노이즈 주입 범위로 그대로 활용 — 임의의 넓은 범위 대신 실측 기반 도메인 랜덤화 |
| sim 보상은 완벽한 성공판정, real은 3단 분류기에 의존 | 3단 분류기의 정밀도·재현율을 사람 라벨 대비 사전 검증, 분류기 오류율 자체를 sim 보상 계산에도 주입(분류기가 100% 정확하다고 가정하지 않음) |
| sim은 이상적 실행, real은 그립 epsilon 불일치·MoveIt2 경로 변동성·충돌 등 추가 실패 모드 보유 | Phase 1 실물 베이스라인 실행에서 측정한 실제 그립 실패율/충돌 빈도를 sim의 확률적 행동 실패 모델에 반영 |
| 물체 물성(마찰·질량) 불일치 | 실제 쓰는 물체(5cm/3cm 큐브) 실측 물성 범위로 도메인 랜덤화 범위 한정(임의로 넓게 잡지 않음) |
| sim에서 학습한 이산 시점이 실물에서 IK/충돌상 도달 불가능할 수 있음 | 후보 시점 집합 K개를 먼저 실물 MoveIt2 plan-only로 전부 도달가능성 검증한 뒤에만 action space에 포함 |

## 6. 2~3개월 단계별 로드맵 (MVP 우선, 점진 확장)

| Phase | 내용 | 기간 |
|---|---|---|
| 0 | **GPU/Isaac Sim 실행가능성 확인(최우선)**, eye-in-hand 캘리브레이션 전환, 저차원 state 추출기 실물 구현 | 1~2주 |
| 1 (MVP) | B0/B1/B2 규칙 기반 베이스라인 실물 구현 + 3단 분류기 검증 — 이 자체로 독립적으로 쓸 수 있는 1차 결과물 | 2~3주 |
| 2 | Isaac Sim 디지털 트윈 구축, Phase 1 실측 통계를 도메인 랜덤화에 반영 | 3주 |
| 3 | Isaac Lab 환경(Gym wrapper) 작성 + RL 학습(저차원 state, 64~256 병렬 환경, PPO 등) | 3주 |
| 4 | Sim-to-Real 전이, 실물에서 RL vs B0/B1/B2 비교 | 2주 |
| 5 | 평가·통계분석·논문화 | 2주 |

(Phase 0 결과에 따라 Phase 2~4는 전면 재설계될 수 있음 — GPU가 부족하면 외부 워크스테이션 활용 또는 병렬 환경 수 축소/저차원 state 전용 경량 시뮬레이터 대안도 검토 필요.)

## 7. 최신 연구 대비 차별성 / 논문 가능성

기존 조사(active_perception_closed_loop.md 등)에서 확인된 논문들(GraspView, Semantic-Aware NBV, GTP-FA, VLCP, PLanAR)은 (a) 시점 선택을 휴리스틱 정보이론적 점수나 VLM 판단으로 처리하거나, (b) 실패 후 보정을 고정된 한 가지 전략(같은 시점 재관측, 또는 VLM이 매번 새로 판단)으로 처리할 뿐, **"관측 비용과 행동 비용을 명시적으로 포함한 보상으로, 관측/파지/재시도/포기를 하나의 정책이 장기적으로 최적화하도록 RL로 학습"**한 사례는 확인되지 않았다. 더하여 이 정책의 보상/성공판정을 실물에서도 구조화된 트레이로 거의 공짜로 얻을 수 있다는 점은, 대부분의 sim-trained active-perception 연구가 실물 전이 시 겪는 "보상 신호 소실" 문제에 대한 구체적 해법이 된다. 이 두 가지(비용인식 RL 정책 + sim과 동형인 실물 보상 신호)의 결합이 핵심 novelty 주장이 될 수 있다. 다만 이 주장이 성립하려면 Phase 1(규칙 기반)과 Phase 4(RL) 비교에서 RL이 "보상을 정확히 맞추려 조심스러워진 것"이 아니라 실제로 더 적은 비용으로 더 높은 성공률을 낸다는 걸 수치로 보여야 하며, 이건 사전에 보장되지 않는다(학습이 실패할 수도 있음을 염두에 둬야 함).
